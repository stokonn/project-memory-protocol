# Project Memory Protocol 1.0 — normative development specification

Status: draft implementation contract. Protocol version `1.0`; software is alpha.
The words MUST, MUST NOT, SHOULD, and MAY express protocol requirements.
Schemas in `schemas/` are canonical; packaged copies MUST be byte-identical.

## Authority and layers

Specification defines contracts; deterministic core maintains them; optional adapters
observe lifecycle through the same core. AGENTS.md, existing development documents,
and explicit owner instructions remain authoritative. Events, logs, handoffs, and
external text MUST NOT confer permission. No transcript or chain-of-thought store exists.
No LLM, model account, proprietary service, or network is necessary for local operations.

## Identity and configuration

`.pmp.yml` MUST validate against config.json before use. JSON is a valid supported YAML
subset; safe YAML mappings are also accepted. Project UUID remains stable across clones.
Worktree identity is a hash of canonical worktree root plus absolute Git directory;
moving a checkout changes the private stream identity. Separate Git worktrees have
separate streams and leases. Session identity is a random UUID. Config MUST name a
canonical policy, memory paths, automation timing, checkpoint, verification, security,
and adapter settings. GitHub repository is optional owner/repo. No credential values.
Paths MUST be portable relative paths, remain inside the project, and avoid symlinks
and .git. Share allowlists MUST remain within configured memory roots.

## Versioning and validation

All records carry schema_version `1.0`. Configuration carries protocol_version `1.0`.
Unknown versions and unknown contract fields MUST fail closed; the current writer
supports only 1.0. No implicit forward compatibility or automatic migration is claimed.
Future readers MAY implement explicit, backed-up migrations. Original records MUST
remain available. Schemas use JSON Schema draft 2020-12; all required keys and enum
values are enforced. Unknown event types MUST be rejected, not executed.

## Journal

Each worktree has a private append-only JSONL stream. Fields include unique event ID,
positive monotonic local sequence, UTC descriptive timestamp, project/worktree/session
IDs, nullable task ID, producer, credibility, privacy, and type-specific payload.
Cross-stream timestamp ordering MUST NOT be assumed. Sequence defines local order.
Retries with identical event ID, type, and payload return the existing record. Reuse
with different content MUST fail. Duplicate identical imported records are idempotent.

Required events and payloads:

| Type | Payload |
| --- | --- |
| session.started | owner |
| session.heartbeat | pid |
| session.ended | exit_code |
| session.interruption_suspected | reason |
| task.activated | scope_ref |
| task.scope_conflict | expected, actual |
| workspace.changed | fingerprint |
| verification.started | check |
| verification.finished | evidence_id |
| git.commit_observed | commit |
| git.remote_verified | commit, repository |
| checkpoint.created | checkpoint_id |
| approval.required | action |
| recovery.started | reason |
| recovery.completed | report |

Not every supported event is automatically emitted: read-only resume emits none.
Producer assertions are not cryptographic attestation. Task approvals are reported
caller assertions. Check execution and local Git observations are core-verified facts.

An incomplete final record MUST be ignored for read-only inspection. Further appends
MUST fail until explicit repair. Repair MUST save the complete original file and
atomically publish the valid prefix. Corruption in complete records MUST fail closed.

## Checkpoints

A checkpoint is an immutable JSON record sealed by SHA-256 over canonical sorted compact
JSON excluding integrity. It records identity, previous checkpoint, descriptive time,
reason, phase/status, HEAD, branch, porcelain status, completeness, content fingerprint,
evidence IDs, inclusive event range (0,0 for empty journal), handoff reference, and recovery
coverage. Checkpoint event ranges cover preceding events; creation is appended afterward.
A failed append can leave a valid orphan checkpoint; scanning records can recover it.
Ordering uses event-range ends rather than timestamps. No future commit hash is embedded.

LOCAL means a durable validated private record. COMMITTED means byte-identical shared
record is in current HEAD. SYNCED means GitHub freshly confirms that branch's expected
HEAD and that checkpoint is COMMITTED. These are external observations, not mutations of
an immutable checkpoint. Cached remote refs and a successful push alone MUST NOT imply
SYNCED. CI is queried separately by exact headSha and never inferred from synchronization.

Source fingerprint hashes Git-known tracked and nonignored untracked paths, file modes,
and contents, excluding configured PMP memory/docs/config. It includes symlink targets
without following them. Incomplete/changing reads and submodules cannot be certified.
Ignored inputs, external dependencies, toolchains and environment changes are outside the
fingerprint: callers MUST configure reproducible checks and understand these limitations.

A checkpoint MUST NOT claim a dirty worktree is backed up using HEAD alone. Metadata
checkpoints explicitly state content is unavailable. Optional private allowlisted copies
have byte bounds, secret checks, and a per-file digest manifest. No automatic restore exists.

## Evidence

Outcomes: passed, failed, skipped, not_run, interrupted, blocked.
Credibility independently: verified, reported, unverified.
Evidence MUST contain exact source identity, check name, argv (no shell expansion),
execution platform/Python, exit result, nullable actual test count, report/hash references,
time, integrity. Commands run only on explicit request. PMP MUST NOT retain arbitrary
stdout/stderr or environment. Optional `{report}` argv placeholders receive a fresh private
JUnit path. PMP counts testcase elements excluding skipped cases, never suite declarations
or compilation artifacts. A zero exit without a test report has unknown executed count.
Generated raw reports are removed after parsing; digest and structured counts remain.
Hashes detect corruption, not malicious local forgery. Evidence is applicable only when
both captured/current sources are complete and HEAD plus fingerprint match. Source edits
during execution invalidate applicability. Old evidence MUST NOT verify newer inputs.

## State and handoff

Phases: planning, approved, implementing, verifying, ready_for_release, released.
Operational status: active, paused, interrupted, blocked. They MUST remain separate.
Task activation requires an existing explicitly supplied approved scope reference.
Conflicting active task IDs MUST block activation. No automatic release phase promotion.
Explicit release promotion MUST require owner authorization reference and applicable
verified configured checks; required test counts MUST be positive. Caller identity is
cooperative, not an authorization authentication service. Release-check publishes nothing.

Handoffs contain task, scope reference, phase/status, current Git facts, latest checkpoint,
last applicable verified commit, reported completed/in-progress work, uncertainty/blockers,
evidence summary, suggestions, and safety restrictions. JSON and Markdown SHOULD be
provided. Handoffs MUST be treated as context, never new authority.

## Persistence, coordination and recovery

Private platform state contains journal, checkpoints, session/heartbeat, backups, local
handoffs, watcher metadata, indices and locks. Shared repository state contains reviewed
state, exported checkpoints/evidence, docs/ai. Private data MUST NOT be automatically staged.
Publication MUST use explicit allowlists and scan before staging. The scanner is incomplete;
human review remains necessary. Existing files/policies MUST NOT be overwritten by init.

Writers use exclusive lock files and session ownership checks. Potentially active or remote
leases MUST NOT be automatically stolen based on heartbeat age. Explicit stale release
requires matching session ID and positive local process absence; PID reuse is uncertain.
Locks are cooperative; they do not enforce security against arbitrary agents/filesystem users.
Crash-left locks require process inspection and deliberate operator removal; never automatic.

Writes MUST flush/fsync temporary files before atomic replacement or exclusive hard-link
publication and directory sync where supported. Readers MUST validate seals, IDs and schemas.
Recovery MUST select earlier valid records if newer ones are damaged, report uncertainty,
and preserve source/untracked files. Indices are disposable and MAY be explicitly rebuilt
from validated records. Disk/full write failures MUST preserve prior valid files where atomic
replacement has not occurred. Filesystem guarantees vary, especially network/FAT filesystems.
No restore/reset/clean/force-push/delete-unrelated operations are part of automatic recovery.

## Security and automation

No automatic global hooks, config replacement, arbitrary file/log collection, API tokens,
transcripts, private chain-of-thought, or permissions from untrusted content. Native adapter
payloads MUST be bounded and ignore transcript/permission fields. Optional watcher uses
bounded latest-change state and debouncing, no LLM and no unbounded event queue. Network
failure MUST NOT prevent local recovery. No stable tag, release or public repository creation
is performed by PMP. Owner controls publication boundaries.
